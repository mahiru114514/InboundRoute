# 离线问路包：线路身份与英文字段修复

> 后续进度：本文记录的站名/道路名翻译边界已在 2026-10-09 扩展。当前离线包用联网核录的本地译名表补齐地名，并修复旧混合字段。详见[离线卡片地名翻译修复](离线卡片地名翻译修复-2026-10-09.md)。

针对实际导出 HTML 里出现的两个问题：

1. 英文包里线路行显示成 `Line 900000160000 · 市域机场线(浦东1号2号航站楼--虹桥2号航站楼)`——把三方的内部线路主键当成了线路号；
2. 英文包里站名、线路名、步行指引仍是中文，只有界面标签是英文。

## 根因

高德 buslines 只给中文线路名和内部 id（`providers.py` 原先把 `id` 直接当 `line.code`），
并且**从不填** `name_en` / `access_no` / `access_name_en` / `walk_note_en`，
而接口层（`offline_view.js`）对缺失字段只做「有就显示、没有就不显示」，于是英文包里只剩中文。
线路名括号里的起讫点（唯一的方向线索）也从未进入契约的 `direction` 字段。

## 改了什么

| 文件 | 改动 |
| --- | --- |
| `modules/route_adapter/normalize.py` | 新增纯函数：线路名拆解、短线号与英文名派生、行车方向推导、出入口编号与英文名派生、高德步行指令的英文句式翻译 |
| `modules/route_adapter/providers.py` | 高德通道改用上述函数：**不再下发三方 id**；填 `name_en`、`direction`、`access_no`、`access_name_en`、`walk_note_en` |
| `modules/route_adapter/data/curated_rail_lines.json` | 新增：上海具名线路的官方英文译名表（数字线路按编号直译，不查表） |
| `modules/offline_kit/package.py` | 把 `direction` 带进离线包（`direction_zh` / `direction_en`）；**打包期补齐英文字段**（见下）；线路号规整为短线号，三方主键不进包 |
| `modules/web_workbench/web/offline_view.js` | 线路行改为「以线路名为主」：只显示真正像线路号的短号，方向另起一行；主键与重复号码不再显示 |
| `modules/web_workbench/web/style.css` | 预览区方向行样式 |

打包期补齐（第二道保险）：老行程的路线快照是修复前算的，里面没有 `name_en` / `direction` / `access_no` /
`walk_note_en`。离线包在打包时用 route_adapter 的**同一套纯函数**从中文字段派生补齐，
所以**只要重新生成离线包就能拿到英文，不必先重算交通**。快照里已经有英文时一律以快照为准，不覆盖。

派生规则（全部可确证，派生不出来就留空）：

- 数字线路 `2号线` → `code=2`、`name_en=Line 2`；`闵行18路` → `code=18`、`name_en=Bus 18`（编号与语言无关，可直接译）。
- 具名线路查译名表（如 `市域机场线` → `Airport Link Line`），查不到保持中文。
- 行车方向只在「下车站恰好是线路名括号里的某一个终点」时才生成 `往X方向`；
  括号顺序不作为方向依据，两边都像或都不像一律不给方向。
- 方向推不出来时**保留完整原名**（含括号），不摘除、不丢信息。
- 出入口 `2号口` → `access_no=2`、`access_name_en=Entrance 2 / Exit 2`；
  站名式的 `浦东1号2号航站楼` 不会被误当成出入口编号。
- 步行指引按固定句式翻译（`步行24米右转` → `Walk 24 m, turn right`），道路名与站名保留中文。
  复合动作按已知片段拆开再连接（`左转进入右侧道路` → `turn left and enter the road on the right`），
  也覆盖空动作（`步行98米`）、`沿X步行N米到达Y`、`到达目的地` 等实际出现的句式。
  **能翻的片段翻成英文，翻不出的片段原样保留**（不猜义、不丢信息）；整句一个片段都翻不出时才留空。
  用实际行程里存的 18 段、119 个高德中文片段实测：**119/119 全部有英文**（改造前有 6 个片段翻不出来）。

## 边界（刻意不做）

- 不翻译三方独有的站名。`虹桥2号航站楼` 这类只有高德知道、curated 站台库里也没有的站名保持中文——
  编一个英文名等于造假数据，也违反 C-铁律-1「缺失时隐藏而非显示占位」。
  要补只能往 `modules/route_adapter/data/curated_stations.json` 里加**真实**英文名。
- 英文句子里的站名仍用中文（如 `Towards 虹桥2号航站楼`）：站名要拿去和站牌、司机对照，不能翻。
- 译名表里的官方英文名需要人工复核后再扩充；表里没有、又不是数字线路的具名线路（如 `隧道夜宵线`）保持中文。
- 行车方向只在能确证时给出。实测该行程 84 条线路条目里只有 4 条能确证（市域机场线的两段）；
  其余 80 条**保留带起讫点的完整原名**（如 `闵行18路(合川路虹泉路--金辉路保乐路)`），
  没有方向也不猜——猜错方向会让乘客上反车，比不给方向更糟。

## 生效方式

- **只重新生成离线包**即可拿到英文：线路名与英文名、行车方向、进出站口编号与英文名、
  中英双语的步行指引都由打包期补齐（不需要重算交通，也不占用三方调用额度）。
- **重算交通仍然更完整**：方向与站口信息来自当时的三方返回，重算后快照本身就带英文，
  加上站台库补全的线路与进出站口，信息最全。

### 为什么「重新生成」了还是中文

英文与方向在**计算交通时**会写进路线快照（`transit_from_previous` / `end_transit`），
离线包会把快照里的字段搬过来；快照里没有时由打包期补齐（本节改动之后的行为）。
本文件记录的第一版只在计算期补齐，因此那时「只重新生成、没重算交通」会仍然是中文。

判断手上那份导出件是新是旧，看两个特征即可：

| 现象 | 说明 |
| --- | --- |
| 已经没有 `Line 900000160000` 这类长数字 | 渲染层是新的（这一条不需要重算就生效） |
| 步行指引只有中文、没有 `往…方向`、没有进出站口编号 | 若还出现，说明打包期补齐没生效（模块需重启加载新代码） |

实例（`data/trip_engine/trips/trip_6cca51e5c503.json`，2026-10-08 01:41 的快照）：
108 个 `walk_note_en` 全为 `null`、`direction` 0 处、42 处 `"code": "310…"`、`access_no` 全空。
用新版打包器重建后：84 条线路条目 0 个长数字主键、78 条有英文名、30 个进出站口全部有编号与英文名、
66 段步行指引全部有英文，问路卡重新出现 `station_entrance` / `station_exit`。

（实例：`data/trip_engine/trips/trip_6cca51e5c503.json` 的 108 个 `walk_note_en` 全为 `null`、
`direction` 0 处、42 处 `"code": "310…"`，即 2026-10-08 01:41 重算前的快照。）
