# 地图接入指引

用户首次接入请先阅读[高德 API Key 配置教程](高德API配置教程.md)，其中提供申请 Key、命令行配置、验证及启动步骤，并说明后续服务器接入计划。

> 本项目把地图展示和服务端路线计算分开：地图 JS key 用于底图，Web服务 key 用于真实交通。没有 key 时可演示，但不能把示例路线当真实导航。

## 零、地图方案与使用范围

| 方案 | key | 说明 |
| --- | --- | --- |
| Leaflet + 默认高德瓦片 | 当前实现不需要 | 未使用官方 JS API；可访问不等于已获得长期或商用授权，公开交付前核实服务条款 |
| Leaflet + OSM 瓦片 | 不需要 | 须保留署名并遵守缓存、请求标识和禁止批量下载等[瓦片使用政策](https://operations.osmfoundation.org/policies/tiles/) |
| 高德官方 JS API | AMAP_JS_KEY + 安全密钥 | 官方地图展示；额度与使用许可按账户控制台及官方条款核对 |
| 高德 Web服务 | AMAP_WEB_KEY | 服务端公交、驾车、步行计算；与 JS key 不互通 |

截至2026-10-03，[高德定价页](https://developer.amap.com/upgrade)按认证类型列出**免费月配额**，不能继续按“个人免费日配额”描述。免费额度有认证时间及非商业使用条件，以你的账户控制台为准；本项目不替用户开通付费。

**模块会自动选择**：设了 `AMAP_JS_KEY` 就走高德官方，没设就走 Leaflet；也可以用 `MAP_PROVIDER` 强制指定。

## 一、本地演示启动

**什么都不用做。** 直接启动：

```powershell
# 在解压后的项目目录运行
python start_software.py --all
```

模块日志会显示：

```
地图：Leaflet + 免费瓦片（无需 key）；瓦片 https://wprd0{s}.is.autonavi.com/...
```

页面「POI 选点」左上角标签变成「Leaflet 地图」，看到真实中文路网。

**换 OSM 底图**（境外网络更稳，或高德瓦片被限制时）：

```powershell
$env:MAP_PROVIDER="leaflet"
# 用环境变量或管理页面配置覆盖瓦片地址：
#   tile_url = https://tile.openstreetmap.org/{z}/{x}/{y}.png
#   tile_crs = wgs84      （OSM 是 WGS84，不需要 GCJ-02 转换）
```

**故意不要底图**（回到示意地图）：

```powershell
$env:MAP_PROVIDER="none"
```

## 二、升级到高德官方 JS API（可选）

### 2.1 你要申请的是哪一种 key

高德 key 按「服务平台」分类型，**这一步选错后面全白做**：

| 平台 | 用途 | 需要吗 |
| --- | --- | --- |
| **Web端(JS API)** | 网页里显示底图（`<script>` 加载 JS API） | ✅ **就是它** |
| Web服务 | 服务端调 HTTP 接口（路线规划、POI 搜索、逆地理编码） | ❌ 那是开发者 C 的 `route_adapter` 要用的，**拿它显示不了地图** |
| Web端(JS API) + Web服务 | 两者都勾 | 也可以，一期只需要 JS API 那部分 |

**记住两个字符串**（第二个只显示一次，丢了要重置）：

- `key`：形如 `1a2b3c4d5e6f7g8h9i0j…`（32 位十六进制）
- `安全密钥`（`securityJsCode`）：形如 `a1b2c3d4e5f6…`

> ⚠️ **2021-12-02 之后申请的 key 必须配安全密钥**，否则高德会返回 `INVALID_USER_SCODE`。见[官方准备文档](https://developer.amap.com/api/javascript-api-v2/prerequisites)。

### 2.2 控制台上的具体步骤

1. **打开控制台** https://console.amap.com/dev/key
   - 没账号先注册开发者；**个人认证免费**（身份证，一般即时通过）
   - 若创建 Key 时被拦，先去 https://console.amap.com/dev/user/permission 完成认证
2. **应用管理 → 我的应用 → 创建新应用**（名称随便，如 `InboundRoute`）
3. **在新应用里点「添加 Key」**
   - Key 名称：`inboundroute-web`
   - **服务平台：务必选 `Web端(JS API)`**
     - 选了 Android/iOS 会要求填 `SHA1`、`PackageName`——那些是移动端签名用的，网页用不上
     - 「可使用服务」应显示 JS API 相关项，而不是 `Android地图SDK`
   - 勾选需要的服务项（地图相关）
   - 提交
4. **复制两个值**：列表里的 `Key` 和 `安全密钥(jscode)`
5. **域名白名单**（建议）：加 `127.0.0.1` 和 `localhost`
   - **只填域名，不要填端口**——模块端口是运行时随机分配的

### 2.3 配置进项目

**推荐：环境变量**（不写入配置文件；浏览器地图 SDK 仍需要收到 JS key，不能视为服务端秘密）

```powershell
# 在解压后的项目目录运行
$env:AMAP_JS_KEY="你的 key"
$env:AMAP_SECURITY_CODE="你的安全密钥"
python start_software.py --all
```

**备选：模块配置**（管理页面 → web_workbench → 配置；会被页面展示，仅本地演示可用）

```json
{
  "amap_js_key": "你的 key",
  "amap_security_code": "你的安全密钥",
  "amap_version": "2.0",
  "amap_plugins": ["AMap.Scale", "AMap.ToolBar"]
}
```

改完**先停止再运行**该模块（宿主不支持热更新）。

### 2.4 怎么确认接好了

日志应显示：

```
地图：高德 JS API v2.0；安全密钥已配置
```

页面上标签变为「高德地图」。F12 控制台的常见报错：

| 报错 | 原因 | 怎么修 |
| --- | --- | --- |
| `INVALID_USER_SCODE` | 安全密钥没配或配错 | 检查 `AMAP_SECURITY_CODE`，重启模块 |
| `USERKEY_PLAT_NOMATCH` | key 类型选错（选成 Web服务了） | 回控制台新建 `Web端(JS API)` 的 key |
| `Refused to load the script ... CSP` | 模块没读到 key，CSP 仍是 Leaflet/严格模式 | 确认日志显示「安全密钥已配置」；改配置后要重启模块 |
| `INVALID_USER_DOMAIN` | 域名白名单没放行 localhost | 控制台白名单加 `127.0.0.1`、`localhost` |
| 地图空白但有底图 | 坐标偏移 | 已按瓦片域名自动选 `tile_crs`（高德=gcj02），若仍偏请截图 |

## 三、两个必须知道的约束

**① CSP 按所选底图动态放宽，不用底图时保持最严。**

工作台默认 CSP 是 `script-src 'self'`。不同方案放行的域名不同（`build_csp()` 按 provider 生成，有测试断言）：

| 方案 | 放行 |
| --- | --- |
| `none` | 什么外部域名都不放行 |
| `leaflet` | `unpkg.com`（SDK）+ `*.autonavi.com` / `*.amap.com` / OSM（瓦片） |
| `amap` | `webapi.amap.com`、`a.amap.com`（SDK）+ `restapi.amap.com`（服务） |

**为什么高德方案不能自托管 SDK**：官方明确要求**在线加载 JS API，禁止本地转存或与其它代码混合打包**（[加载文档](https://developer.amap.com/api/javascript-api-v2/guide/abc/load)）。所以只能放行域名，不能把 SDK 打进包。Leaflet 是 MIT 开源，理论上可以自托管，但现在走 CDN 更省事（已实测可达）。

**② 高德方案的安全密钥走「明文方式」。**

官方推荐用 Nginx 反代把密钥留在服务端。本项目走的是官方文档里也写明的明文方式（`window._AMapSecurityConfig.securityJsCode`），因为不用 Nginx。对本地演示可接受（key 有域名白名单、配额可限），但：

- **不要**把 key 提交到公开仓库（用环境变量就是为了这个）
- **不要**把带 key 的页面部署到公网
- 将来要上公网，改成官方推荐的 Nginx 反代方案；代码里已有 `security_mode` 字段区分两种模式

> 另一条路更简单：**就一直用 Leaflet 方案**。它没有密钥泄露问题——高德公共瓦片不需要 key。什么时候需要官方 JS API 呢？当你需要**官方 POI 搜索、官方路线规划插件**的时候（那属于 C 的 `route_adapter` 范畴）。纯展示底图，Leaflet 完全够。

## 四、接好之后会发生什么

底图就绪后这些行为自动生效（`web/map.js` 已实现并有单测）：

| 图钉状态 | 视觉 | 触发条件 |
| --- | --- | --- |
| `default` | 白底圆点 | 未加入任何一天 |
| `added_current_day_unselected` | 浅绿 + 灰序号 | 已加入当前浏览天但未点击 |
| `added_other_day` | 灰白 + `D2` 角标 | 已加入其他天（多天时 `D2/D5`） |
| `selected_current_day` | 深绿放大 + 序号 | 当前选中的点 |
| `added_conflict_warned` | 红色 | 用户对硬冲突点了 Proceed anyway |

**「行程概览」里有 Day 切换标签**：点 Day 2 → 属于 Day 1 的点立即变灰、Day 2 的点变浅绿。这就是状态机的实际效果。

> `added_conflict_warned` 现在触发不了，它依赖 B 的 `rules_engine` 产出 `rule_notices`。等 B 接入后自动生效，前端不用改。

### 视野策略：默认只看市中心，另有「显示全部」

上海的空间尺度大（PRD 1.2 说的「地理尺度失真」）：市中心三个点只相隔 1.7 公里，而朱家角在西北约 **40 公里**外。
若一开始就把所有点框进画面，市中心会挤成一团、图钉互相压住。所以：

- **默认**：用「最密集的一簇」算法只框住市中心点位，图钉分得开、看得清
- **右上角「显示全部」**：切到全览，朱家角进画面，市中心被压缩（这时锚点自动隐藏，因为显示它没意义）
- **锚点避让**：酒店锚点与最近 POI 距离小于 400 米时自动推开约 350 米，避免两个图钉完全重叠；锚点始终在最上层（`zIndexOffset` 300 > POI 的 100/200）

这套逻辑都是纯函数（`densestCluster` / `anchorOffset`），在 `tests/map_states.test.js` 里有单测覆盖。

## 七、启用并验证真实路线

1. 高德控制台申请 **Web服务** key，核对路径规划权限、额度和IP白名单。
2. 在启动软件的同一个 PowerShell 进程配置 `$env:AMAP_WEB_KEY="你的Web服务key"`。不要把 key 发进聊天、截图或代码库。
3. 管理页面的 route_adapter 配置设 `provider` 为 `amap`，`providers.amap.city` 为 `上海`，停止后重新运行该模块；JS地图 key 不需要改。

```json
{"provider":"amap","providers":{"amap":{"city":"上海","timeout_seconds":5}}}
```

先用独立工具验证，工具不修改业务配置或已有行程，每种方式发一次请求：

```powershell
# 在解压后的项目目录运行
python -X utf8 tools/smoke_amap.py --modes walk,taxi,transit --require-key
```

`passed` 才代表拿到真实耗时、距离和公交分段；`failed` 需检查配置/权限/网络。没有环境变量时 `skipped` 表示**没有验证**，`--require-key` 会返回退出码2。输出不包含 key 和请求 URL。

失败时查看 `diagnostic` 和 `hint`。`reason=partial_data` 是兼容业务降级逻辑的通用原因，不能单凭它判断 Key 是否正确。工具会保留安全的高德错误码 `provider_code` 或 HTTP 状态 `http_status`，并区分网络、DNS、证书、响应解析和路线字段缺失。不要关闭 HTTPS 证书验证来绕过证书问题。

| 诊断 | 下一步 |
| --- | --- |
| `provider_code=10001` | 核对 Key 是否复制完整、是否仍有效 |
| `provider_code=10009` | 核对使用的是 Web服务 Key |
| `provider_code=10005` | 核对请求出口 IP 是否在 IP 白名单内 |
| `provider_code=10002` / `10012` | 核对路径规划服务权限；10002 也可能是接口路径错误 |
| `category=certificate_error` | 检查系统时间、Python 信任证书及代理证书配置 |
| `category=missing_route_fields` | 高德返回的路线缺少距离或耗时，需要检查数据格式 |

其他服务错误按[高德官方错误码说明](https://developer.amap.com/api/webservice/guide/tools/info)排查。把工具输出发给开发者即可，不需要提供 Key。

如果步行、驾车已通过，但公交仍失败，单独运行以下命令，每次只发一次公交请求：

```powershell
python -X utf8 tools/smoke_amap.py --modes transit --require-key --diagnose
```

`walking_duration_missing` / `ride_duration_missing` 表示对应路段缺少有效耗时；`unsupported_transit_segment` 表示解析器遇到了火车或出租车字段；`transit_segments_missing` 表示未解析出任何路段。`response_summary` 只包含字段状态和数量，用于判断空占位字段、步行 steps 和 buslines 的结构，不包含原始响应、站点名字、坐标、请求 URL 或 Key。真实数据确认前，不把缺失耗时填成 0 或用估算值冒充真实数据。

2026-10-04 修正：高德可能用含空数组、空字符串或空对象的 `railway` / `taxi` 对象表示没有该类路段。解析器现在按字段中是否存在实际内容判断，忽略这些空占位对象；真正含有火车、出租车数据的方案仍返回 `unsupported_transit_segment`。诊断工具和解析器共用同一判断，避免诊断显示无数据但解析器仍拒绝。用户提交的结构摘要确认：步行总耗时和公交耗时有效，因此无需依赖步行 steps 内的耗时。

### 独立测试通过，但工作台仍显示路线不可用

先查看 `logs/route_adapter.log`。若出现 `amap 未配置 API key`，表示正在运行的路线进程没有读到 Key。PowerShell 的 `$env:AMAP_WEB_KEY` 只影响这个终端随后启动的子进程；旧管理台及其已运行的模块不会自动获得它。仅关闭浏览器、在旧管理台点“运行”，或者另开终端启动时复用仍运行的模块，无法解决该问题。

1. 到原来的启动终端按 Ctrl+C，等待管理台和它启动的模块退出；若有另一个管理台窗口，也要结束它。
2. 回到独立测试成功的 PowerShell，用 `[bool]$env:AMAP_WEB_KEY` 确认返回 `True`（只显示有无变量，不显示 Key）。若返回 `False`，在本机重新设置该变量。
3. 在同一终端运行 `python -X utf8 start_software.py --all`。
4. 刷新工作台后重新计算交通；检查来源为 `amap`，且有真实耗时。

代码已修正：缺 Key 时 `/health` 返回 `ready=false`、`degraded_reason=provider_not_configured`，工作台会提示从配置环境变量的终端重新启动；三方返回预期错误时，路线接口返回契约允许的降级数据，不再直接断开 HTTP 连接，也不会缓存该失败结果。健康状态只检测是否配置了 Key，不代表 Key 的权限、额度或实际请求必定成功。

回到工作台，在⑤点击“计算全部区间交通”，确认来源为 amap，检查采用方式、时间轴及离线包。驾车方案的打车费用是估算，不能代替实际网约车报价。路线 API 不会自动补齐景点营业时间和亮灯信息，请以场馆公告为准。
