# 推荐行程设计草案

状态：用户已确认，进入实现。日期：2026-10-06。

## 目标

用户自行填写酒店、抵达/返程口岸、日期和时刻，选择兴趣、同行人群及游玩节奏，点击一次「生成推荐行程」，获得中间游玩日的景点组合与顺序。生成结果使用现有行程结构，用户可以继续增加、删除、排序、跨天移动和锁定点位。

本轮覆盖上海已有景点数据，不扩展城市。机票输入以出行时间和口岸为主，不增加机票搜索、价格推荐或预订。酒店不由推荐引擎选择：沿用住宿候选和地图定位，并支持填写自己的住宿名称及位置，供行程起终点使用。

## 三种实现方式

| 方式 | 优点 | 限制 |
| --- | --- | --- |
| 规则排程（推荐） | 按当前日期、兴趣、节奏与酒店位置生成，可解释，可做确定性测试 | 推荐多样性依赖已有景点资料；需明确处理开放信息缺失 |
| 固定行程模板 | 易维护，可体现人工组合经验 | 天数、日期和住宿变化后仍需调整，个性化较弱 |
| AI 生成 | 可以接受更自由的文字偏好 | 需要模型接入，并额外校验返回景点、时间和约束，不能直接写入行程 |

首版采用规则排程，后续可以叠加人工主题模板或 AI 意图解析。

## 用户流程

1. 用户填写基本设定：日期、天数、酒店及位置、抵达和返程时间、兴趣、同行人群、节奏。未填写的必需项在表单中提示，不留下半份推荐行程。
2. 展示「推荐安排哪些天」的选择项。默认选择首尾之间的游玩日，例如 5 天行程默认选第 2、3、4 天；抵达和返程日不会被自动加入。用户可以自行勾选其他天。1～2 天行程默认不勾选，提示选择想安排的日期，不静默更改首尾日。
3. 点击「生成推荐行程」，自动生成选中日期的游玩内容并在每日行程区展示，附简短理由，例如兴趣匹配、同一区域、兼顾晚间活动。正常首次生成无需再点击逐个加入景点。
4. 用户直接使用现有编辑控件自定义。推荐写入后都是普通可编辑点位，不强制锁定。
5. 已有行程时，默认只填充选中的空白游玩日。有用户安排的日期保持原内容；若所有选中日都有安排，提示改选空白日或复制当前行程后重新规划。首版不提供自动覆盖已有安排。

推荐过程中，酒店和出入境信息不会被替换。按钮运行时显示进度并禁止重复提交；失败时保留表单和既有行程。

## 排程规则

- 兴趣决定景点优先级，同行人群与节奏影响每日数量和停留量；沿用现有轻松、均衡、紧凑的建议上限。
- 按区域聚合，优先减少同一天的远距离来回移动；顺序参考酒店及每日起终点位置。同一景点不跨天重复推荐，也避免重复加入已有安排中的景点。
- 按每一天的实际日期检查已知闭馆和开放窗口；对日期明确不适合的候选进行替换。特殊开放/闭馆规则的优先级与现有规则契约一致。
- 缺少或未经核验的开放信息必须随结果提示，不能表述为已保证可入场；不自动替用户完成预约。
- 优先考虑景点建议停留、每日出发时间，并给交通和休息留余量。数量是上限，不为填满数量而硬塞景点。
- 初步空间排序使用地理距离和规划余量；真实区间交通继续由现有 route_adapter 计算，不能将初步估计标为真实导航或已验证到达时间。
- 候选不足时返回实际能安排的内容和原因。没有合适候选的天明确显示未安排，不复制同一批景点凑满天数。
- 现有整趟预算继续通过预算评估展示；酒店、机票和其他费用缺失时不能承诺生成结果符合整趟预算。

## 模块职责

| 位置 | 职责 |
| --- | --- |
| `modules/recommendation_engine/` | 独立推荐模块，读取行程和 POI，筛选、评分、区域组合及日内排序，返回建议与理由；不直接写行程文件 |
| `modules/trip_engine/` | 继续作为行程唯一持久化方，提供整批推荐点位的原子写入接口；校验版本、目标日与点位，防止部分成功和覆盖用户编辑 |
| `modules/web_workbench/web/recommendations.js` | 日期选择、推荐操作、进度与理由展示；协调生成后刷新现有编辑界面 |
| `modules/web_workbench/` | 代理推荐模块接口与行程批量写入接口，浏览器不接触模块令牌 |
| `contracts/` | 登记推荐请求/响应与批量应用接口；生成结果最终仍遵守现有行程、POI 和停止点结构 |

推荐模块的纯规划代码与 HTTP、上游访问分文件管理。模块通信继续通过本地服务和注册表，不直接导入其他插件的实现。推荐是用户明确触发的新操作，不改变现有 rules_engine「只提示、不自行重排行程」的约定。

## 数据与一致性

推荐请求包含目标行程/基本设定、选中的日期以及现有偏好。响应包含每日建议 POI 顺序、建议停留、推荐理由、数据待核验提示与无法填充的日期。

trip_engine 应用建议时，在同一行程事务中重新核对版本与选中日是否仍为空，校验每个 POI，构造停止点 ID 并一次提交。版本冲突返回明确错误，保留用户最新修改；不采用前端逐个 POST 点位造成半份推荐的方式。

新建行程的「一键生成」先完成输入校验和推荐计算，再持久化完整结果；生成失败不留空壳行程。建议理由和规划提示放在推荐响应及界面中，首版不为它们随意新增冻结行程字段。

## 验收标准

- 5 天行程默认只生成第 2～4 天；用户酒店、抵达和返程设定不变。
- 不同兴趣/节奏会影响生成内容和数量；不会把相同景点反复塞入不同日期。
- 遇到已知闭馆日会替换候选；开放信息缺失会展示核验提示。
- 已有用户安排与锁定点不被自动覆盖；版本冲突、超时及连续点击不造成重复或部分写入。
- 新行程生成失败不落盘；已有行程生成失败不改动原行程。
- 生成后可以增删、排序、跨天移动，既有规则、路线、预算评估和离线流程仍可运行。
- 推荐模块未运行时按钮明确提示原因，手动规划仍可使用。
- 完成推荐单元测试、行程批量写入与并发测试、代理集成测试、页面真实接线测试，并回归现有完整验证脚本。
