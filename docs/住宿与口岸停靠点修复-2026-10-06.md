# 行程停靠点核查与修复（2026-10-06）

当前项目是模块化 Python HTTP 服务；实际工作台位于 `modules/web_workbench/web`。`web/app.js` 是另一套宿主页资源。核查以实际工作台与服务调用链为准。

| 用户提出的问题 | 核实结果与处理 |
| --- | --- |
| 住宿不能进入当天时间轴 | 成立。新增住宿停靠点，可填写 0–720 分钟停留/睡眠，并支持跨零点推算。 |
| 底部缺少收起入口 | 成立。每日详情底部增加收起按钮，收起后定位到该日卡片。 |
| 口岸只能作为隐式边界 | 成立。增加抵达/离境口岸按钮，可选择具体口岸并插入时间轴。 |
| locked 状态从不设置 | 成立。非空日的全部停靠点锁定时为 locked，解锁后恢复按景点数计算的状态。 |
| JS/Python 默认点位规则重复 | 成立。Python 统一解析 resolved_day_points 与 default_day_points；JS 只消费服务端快照。 |
| 连续同名项摘要去重 | 当前版本不成立：day_cards.js 使用 sequence.join，没有去重。不改变这一行为；回归测试保留重复住宿项。 |
| 离线包前锚点时间填充不明 | 原实现无锚点停靠项，所以是扩展风险。现已明确：route_adapter 区段耗时 → rules_engine 顺序推算所有类型的 arrival_at/departure_at → 持久化 → 前后端完整性校验。缺时间或交通的包返回 400；零值合法。 |
| 锚点只能末尾追加且无法排序 | 当前版本没有锚点添加实现。新增选择插入位置，住宿/口岸与景点共享上移、下移、拖拽、跨天移动控件。 |
| poi_id 用 hotel 占位，排序/删除不可靠 | 当前源码没有这一占位实现。但风险成立：新增稳定 stop_id，锚点不再需要虚构 poi_id。旧 poi_id 调用仅在无歧义时兼容。 |
| arrival_only 加 POI 后不更新 | 成立。抵达日期独立保存为 is_arrival_day；有景点时按景点数或全部锁定状态更新 day_status，删除最后一个景点恢复抵达日。住宿/口岸不计入景点建议数量。 |
| addAnchorStop 有能力但没有口岸按钮 | 当前源码未找到 addAnchorStop，原描述与当前版本不符。现在新增函数和三个实际界面按钮。 |
| 移除锚点依赖类型占位 | 原描述与当前版本不符。新界面和后端统一使用 stop_id，重复住宿可以逐项删除。 |

酒店停靠项按最后出现的住宿影响自动终点与后续住宿继承；显式终点仍优先。增删或移动酒店改变后续默认地点时，会清除受影响日期的旧交通与时间。首站为行程抵达口岸时，时间轴展示实际抵达时刻并包含入境缓冲。相同坐标区段保留零耗时，不请求路线提供商、不挤掉区段索引。

旧行程读取时会得到确定性的 stop_id，读取不写盘；下次修改时保存。服务端起终点快照不落盘，每次读取或返回修改结果重新生成。浏览器静态资源版本更新到 22，修改后需重启相关服务并刷新页面。

新增回归：`tests/test_anchor_stops.py`、`tests/test_offline_timeline.py`、`tests/anchor_cards.test.js`，以及 `tests/test_workbench_flow.py` 的机场/住宿/睡眠贯通案例。现有默认地点与导航测试改用 Python 生成的行程快照夹具，避免测试里再次复制规则。

最终验证：行程引擎与新增回归 60 项、规则引擎 79 项、路线适配器 57 项、离线模块 14 项、工作台 HTTP 26 项、跨服务贯通 7 项，合计 243 项 Python 测试通过；12 组 JS 测试通过；契约生成同步检查通过，契约校验 162 项通过。未调用真实付费地图提供商；贯通验证使用项目已有 mock 路线提供商，包含实际临时 HTTP 服务与规则持久化链路。
