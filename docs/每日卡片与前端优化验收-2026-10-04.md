# 每日卡片与前端优化验收

用户批准将每日行程做成摘要卡，展开后处理当天时间轴、景点调整与交通；同时继续采用之前的柔和工具风。

## 已实现

- 每天一张默认收起的卡片，封面展示日期、景点序列、数量、停留时间、游览时段；时间不完整时显示“结束待定”。抵达日从 `activity_start_at` 开始，后续日按每日出发设定。
- 交通缺口、返程待计算、交通方式受限、闭馆 / 时间风险、规则缺少数据和演示来源都在封面提示。时间轴生成并不代表景点运营信息已完整核验。
- 展开后可排序、锁定、移到晚上、跨天移动、移除景点，并直接计算当天交通、选择交通方式。展开本身不调用路线接口。
- 重算与编辑保留当前行程卡片的展开状态；换行程或进入新建状态会清理。服务轮询无数据变化时保留卡内节点与键盘焦点。
- 已保存的去程方案会在当天恢复；酒店返程尚未持久化，刷新后明确显示待计算。
- 切换交通方式时，先合并单模式请求与完整候选，再保存；避免刷新后其他方式丢失。优先打车的自动选择也使用相同逻辑。
- 桌面左侧导航，主区域每日卡片两列；展开卡片占整行，时间轴与交通分列。窄屏单列、顶部横向导航、底部保存 / 重置按钮。
- 已保存行程的设定区默认收起，点击设定或导航可展开。统一颜色、间距、圆角、状态、焦点和弹窗；清理原来多层重复主题覆盖，保留地图图钉坐标与旋转规则。
- 静态资源统一版本13，新增日卡脚本挂载。已重启工作台模块，当前脚本 HTTP 200；未重启其他模块、未计算真实高德路线、未编辑用户保存的行程。

## 配色补充（静态版本14）

根据用户要求增加卡片颜色：每日按日期顺序固定轮换薄荷绿、雾蓝、杏色、淡紫、玫瑰粉、浅青；彩色摘要配深色日期标记及顶部强调线，展开内容保持白底。景点推荐按历史人文 / 现代天际线 / 市井生活 / 自然生态使用对应底色。交通与风险标签的含义不随日期配色改变。

## 交通入口收拢（静态版本15）

用户确认交通已融入每日行程，移除独立的区间交通面板及其导航项。全程计算按钮、服务提示、计算进度移至每日行程区；各区段方案仅在对应日卡内渲染，避免重复列表。离线问路导航顺延为05。编辑行程或切换行程会清除过期计算进度。

七组Node回归全部通过，接线104/104；隔离浏览器112项通过，覆盖五个导航项、全程入口在行程概览、当天方案无重复、全部/单日计算、缺Key提示、方式切换及移动布局。实际运行工作台已经提供版本15页面。未修改路线接口或用户保存数据。


## 每日独立出发时间（静态版本16）

初始设定移除统一出发字段。每张日卡展开后可分别设置当天出发时刻，修改自动保存并进行规则校验；保存全局日期、住宿、偏好不覆盖各天时间。首日允许推迟，实际开始不早于抵达缓冲结束；跨零点仅抵达入住日显示说明并禁用当日编辑。

只修改某一天时仅使该天旧交通和时间轴失效，提示重新计算当天交通；其他天路线保持。输入没有变化不重复提交，保存失败恢复原值，携带If-Match版本校验。

验证：行程引擎HTTP测试45项通过，规则引擎78项通过；七组Node回归通过；隔离浏览器122项通过，覆盖逐天不同时间、重绘恢复、全局保存不覆盖、首日缓冲、保存失败回滚及缺交通提示。生成契约检查无不同步。已按依赖顺序重载行程、规则、路线、离线、工作台模块，均运行且健康检查ok；运行页面提供版本16。未写入用户已有行程，未发出真实高德路线请求。

复核补充：后端同日抵达也会标记 `arrival_only`，因此前端只依据缓冲结束是否跨出当天决定禁用，正常首日可编辑。Node补测同日抵达、跨零点禁用及摘要日期，浏览器首日采用真实 `arrival_only` 状态完成验收。
