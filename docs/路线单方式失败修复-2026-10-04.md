# 单个交通方式失败导致整段不可用

## 复现与根因

现场区间：金茂大厦 → 上海环球金融中心。分别调用正在运行的路线服务得到：公共交通 `no_route`；步行 338 秒 / 423 米；打车 138 秒 / 499 米。公共交通无路线不代表其他方式不存在。

`RouteAdapter.compute_route()` 先取公交方案，在其失败时立即返回空 variants 的降级整段，尚未调用步行和打车，因此页面无法显示或选择可用替代方式，后续时间轴也因缺少这段耗时无法生成。

## 修复

保留各请求方式的独立结果，只有所有请求方式失败时才降级为整段不可用。公交无结果时仍显示步行和打车，保留公交不可用状态；不给缺失耗时填 0，不替用户修改已有交通方式。

页面明确提示「公共交通暂不可用，请选择下方可用方案」，尚未选中有效方式时显示「当前采用：未选择可用方案」。选择可用方式后沿用现有保存路线和重算时间轴流程。

路线模块增加仅包含固定类别与数字错误码的失败日志；不记录 Key、请求 URL、原始提供方消息或异常文本。所有静态资源统一升级为 v=12。

## 验证与现场限制

Python 回归先复现公交失败丢失另外两种方式，Node 回归先复现界面无替代提示，再修复使其通过。测试覆盖 schema、全方式失败、仅请求公交无方案、可用方式保留、禁用不可用按钮及安全诊断日志。

最终验证：53 项路线测试、12 项高德诊断工具测试、Node 流程回归与 102 项页面接线断言通过；75 项隔离浏览器检查也通过。

重启路线模块时，按照模块依赖顺序短暂停止并恢复 offline_kit 与 route_adapter；已保存行程没有改写。重启后现场接口返回提供方代码 **10005**，日志已确认。这是请求出口 IP 不在对应 Key 白名单的独立配置阻塞：[高德官方错误码说明](https://developer.amap.com/api/webservice/guide/tools/info)。

因此不能宣称现场真实路线已经全部恢复。需要在高德控制台核对实际使用的 Web服务 Key 与当前请求出口 IP 白名单，然后重新计算该天交通。浏览器展示的 IP 不一定与服务请求出口一致，若代理或网络发生变化尤其需要核对。
